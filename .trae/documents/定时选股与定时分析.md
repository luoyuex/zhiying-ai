# 定时选股 + 定时分析自选股 实施计划

## Context

五条选股策略与单股 AI 分析均已完成，但全部依赖手动触发。本次实现每日定时自动化：用户可开启「每日定时选股」（可为每条策略自定义筛选参数）与「每日定时分析自选股」，由 ARQ worker 在收盘后（默认 17:35，可配）自动执行并落历史记录，形成 AI 决策闭环的第一环。

已确认的产品决策：
- 用户级开关，默认关闭（需建表迁移 + 前端设置 UI）
- 定时选股 + 定时分析自选股都做
- 选股参数由用户在设置中自定义（复用现有五个策略参数模型校验）

## 核心复用点（已核实）

| 现有能力 | 位置 | 复用方式 |
|---|---|---|
| 选股任务创建（LLM 检查/活跃去重/strict 额度检查/入队） | `backend/app/services/screener_job_service.py::start_screener_job(redis, user_id, daily_quota, strategy, payload)` | 调度器直接调用 |
| 单股 AI 任务创建 | `backend/app/services/ai_job_service.py::start_ai_job(redis, user_id, daily_quota, symbol, force=False)` | 调度器逐自选股调用，force=False 命中 6h 缓存 |
| 五策略参数模型 | `backend/app/schemas/screener.py` 五个 `*AnalysisRequest` | 设置校验 + 调度时反序列化，零重复 |
| 额度 | Redis `quota_key(user_id)`；`settings.effective_daily_quota(user.daily_analysis_quota)`（`core/config.py:95`） | 调度前预检 + start_* 内建 strict 检查 |
| ARQ cron | `backend/app/worker.py` `cron_jobs`（现有 worker_heartbeat 即范例） | 追加每日调度任务 |
| 前端个人中心 | `frontend/src/components/layout/AccountCenterModal.vue`（左侧导航 + 视图结构） | 新增「定时任务」视图 |

## 实施步骤

### 1. 后端配置（`backend/app/core/config.py`）
新增：`automation_cron_hour: int = 17`、`automation_cron_minute: int = 35`。同步 `.env.example`（自动化段落）。

### 2. 数据模型 + 迁移
- 新文件 `backend/app/db/models/automation_settings.py`：表 `user_automation_settings`
  - `id` Uuid PK、`user_id` Uuid unique FK users.id CASCADE
  - `screener_enabled` bool default false、`analysis_enabled` bool default false
  - `strategy_settings` JSONB default `{}`：`{"main_force": {"enabled": true, "filters": {...}}, ...}`（key 即启用的策略）
  - `created_at` / `updated_at`（onupdate）
- 在 `backend/app/db/models/__init__.py` 注册
- 迁移 `backend/alembic/versions/e5f6a7b8c9d0_user_automation_settings.py`，`down_revision = 'd4e5f6a7b8c9'`（当前最新，已核实）

### 3. Schema + 设置 Service + API
- `backend/app/schemas/automation.py`：
  - `AutomationStrategySetting { enabled: bool, filters: dict }`
  - `AutomationSettingsUpdate / AutomationSettingsResponse`
  - `STRATEGY_FILTER_MODELS = {"main_force": MainForceAnalysisRequest, ...}`：filters 非空时 `model_validate` 失败返回 422；通过后 `model_dump(mode="json")` 落库（保证 worker 可直接反序列化）
- `backend/app/services/automation_settings_service.py`：`get_settings(user_id)`（无记录返回全默认）、`update_settings`（upsert）
- `backend/app/api/v1/automation.py`：`GET /automation/settings`、`PUT /automation/settings`（登录保护），挂到 `api/v1/router.py`

### 4. 调度器（`backend/app/services/daily_automation_service.py`）
`run_daily_automation_task(redis)` 流程：
1. `is_llm_configured()` 为假 → 整体跳过并记日志
2. 防重：`SET automation:ran:{YYYYMMDD} 1 NX EX 172800`（上海时区日期）；抢不到直接返回
3. DB（SessionLocal）查 `User.status == "active"` 且开启任一开关的用户（join 设置表）
4. 逐用户 try/except（单用户失败记日志继续）：
   - **定时选股**：对 strategy_settings 中 enabled 的策略，`Model.model_validate(filters)` → `start_screener_job(...)`；`QuotaExceededError` 跳过该用户剩余策略；`LLMNotConfiguredError` / `AIWorkerUnavailableError` 终止本轮
   - **定时分析**：预检额度（`read_quota_used`）→ `list_watchlist`（`watchlist_service`，查确切函数名）取 symbols → 逐只 `start_ai_job(..., force=False)`；`QuotaExceededError` break，单只失败隔离继续
5. 汇总日志：入队数 / 跳过原因

`backend/app/worker.py`：
- `functions` 注册 `run_daily_automation`
- `cron_jobs` 追加 `cron(run_daily_automation, hour={settings.automation_cron_hour}, minute={settings.automation_cron_minute}, run_at_startup=True)`（启动补跑 + 防重键兜底）

### 5. 后端测试（模式参考 `backend/tests/test_screener_jobs.py` 的 FakeRedis/FakePool + monkeypatch）
- `test_automation_settings.py`：默认回显、PUT 后回读、非法 filters 422、未知策略键拒绝、用户隔离
- `test_daily_automation.py`：防重键二次不入队、LLM 未配置跳过、额度用尽跳选股且分析 break、两策略开启入队 2 个 screener job + N 个 ai job、单用户异常不影响下一用户

### 6. 前端
- `frontend/src/api/automation.ts`：类型复用 `api/screener.ts` 的 `ScreenerStrategyId` 与五个 `*AnalysisRequest`；`getSettings()` / `updateSettings()`
- `frontend/src/components/account/AutomationSettingsView.vue` + `AutomationStrategyForm.vue`：
  - 表单采用**配置驱动**（一份字段描述数组渲染数字/布尔项），复用 `ui/Select.vue` / `ui/Input.vue`；不抽五个 Panel 的表单（它们与 useScreenerAI 深耦合，重构成本高）
  - 两个总开关（关闭隐藏对应区块）；策略行 = 启用 checkbox + 参数表单；保存一次性 PUT，无刷新提示；进入视图时 GET 回显（filters 缺失项用模型默认值）
- `AccountCenterModal.vue`：导航加「定时任务」项 + 视图挂载
- 黑白灰主色沿用现有 token
